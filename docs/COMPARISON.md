# 与主流记忆方案的差异对照

> 核对日期：**2026-11-03**。星标为当天 GitHub 页面数字，会漂移；
> 判断依据一律写「它有没有这个能力」，不写「它做得好不好」——
> 一个不需要多租户服务的方案拿"没有鉴权"当缺点，是拿错尺子。

memfade 不是"最大的记忆库"，是"最省心的记忆插件"。这两件事必须分开看，
否则对比就没有意义。

## 零、怎么读这份对照

| 定位 | 谁在跟 memfade 比 | memfade 的位置 |
|---|---|---|
| **库 / 基础设施**（自己建服务、多用户、要鉴权） | mem0、Hindsight、Graphiti、cognee、Letta | **落后，而且是该落后**——它们能做的事 memfade 明确不做 |
| **聊天机器人插件**（装上就能用、复用宿主 LLM、别把 A 的私密记忆漏给 B） | AstrBot / MaiBot 生态里那几十个记忆插件 | **领先一档**——它们多半是"记住 + 向量检索"，没有衰减、没有写入纪律 |
| **成品应用内建记忆**（SillyTavern / Open WebUI / LobeHub / LibreChat） | 官方自带 | memfade 的自由度更高（可换宿主、可自改提炼规则），但它们更省事 |
| **TypeScript 生态的 agent 记忆服务** | OpenMemory | 理念最接近（衰减 + 强化 + 可解释召回），实现栈不同 |

一句话定位：**memfade 站在"中文聊天机器人 + 单人或小群 + 不想再运维一套记忆服务"这个生态位上，
用别人不愿意付的工程代价（写入纪律、作用域隔离、可审计）换"装上就用"。**

## 一、通用记忆层：它们强在哪，memfade 为什么不去追

| 项目 | 星 | 许可 | 记忆模型 | 遗忘 / 淡化 | 部署代价 |
|---|---|---|---|---|---|
| [mem0](https://github.com/mem0ai/mem0) | ~68k | Apache-2.0 | 向量 + 图，实体链接 | **矛盾驱动**（新事实推翻旧事实 → UPDATE/DELETE），**没有"很久没被提起就退场"的时间衰减** | LLM + embedder + Qdrant/Postgres |
| [Hindsight](https://github.com/vectorize-io/hindsight) | ~50k | MIT | 四类记忆库：world / experience / observation / mental model | retain/recall/reflect + 背景巩固（带证据原话与佐证数） | Postgres + pgvector（开发期可嵌入式） |
| [Graphiti](https://github.com/getzep/graphiti) | ~29–32k | Apache-2.0 | **双时序**知识图谱，每条事实带有效期 | 事实按时间失效，可回答"3 月的她住哪" | Neo4j / FalkorDB / Neptune + LLM |
| [cognee](https://github.com/topoteretes/cognee) | ~33k | ECL | 概念图谱管线 | 靠图上的时间维 | 图后端 + 索引 |
| [Letta (MemGPT)](https://github.com/letta-ai/letta) | ~24k | Apache-2.0 | core / recall / archival 三层 | **agent 自己编辑记忆**（运行时，不是记忆层） | 服务端 + 沙箱 |
| [OpenMemory](https://github.com/caviraoss/openmemory) | — | Apache-2.0 | 多扇区（情节/语义/程序/情绪/反思） | **自适应指数衰减 + 共激活强化** + 可解释召回轨迹 | Node 服务 + MCP server |
| [llm-memory](https://github.com/MLidstrom/llm-memory) | — | MIT | 短对话块（单文件 demo） | **指数遗忘曲线，半衰期 90 天 + 情感重要性权重** | Pinecone + Ollama，重 |

> 星标口径不一（同一仓库不同快照能差好几万），上面取的是带日期的那个来源；
> `~50k` 是 2026-10-14 的 repo 元数据（49.7k）。**看星标选型是坏习惯**——
> Hindsight 的作者自己也把"厂商自报分数"和"被独立复现的分数"分开标注。

### 1.1 真正的护城河在哪

**mem0 的强项是写入侧的冲突消解，弱项是没有时间维。**
它能识别"新来的事实和旧的事实矛盾"，然后更新或删除旧的。
但一条**从来没被证伪**的记忆，在 mem0 里永远不会因为"很久没被提起"而退场。
对一个每天聊几十轮的 QQ 机器人，这意味着**库只会单调变大**——
半年前的废话和昨天的约定检索权重一样高。

**Graphiti 的双时序是 memfade 最该学、也最学不动的东西。**
它的每条事实带 `valid_from / valid_to`，于是"她当时住哪"是可回答的。
但代价是一套图数据库 + LLM 实体抽取流水线——
对一个"装个插件就跑"的 QQ 机器人，这个部署门槛是劝退级的。

**Hindsight 的"背景巩固"和"记忆自省"是 memfade 最该学的两件事。**
它的巩固任务在后台把一批记忆归纳成更高层的认知，**且每条结论都带证据原话与佐证计数**
——"这个结论是从哪几条推出来的"是可查的。memfade 现在只压单条摘要（GISTED），
没有"从多条归纳出一条结论"的能力，更没有佐证链。
它也提供 MCP 端点，接入面比 memfade 宽。

**OpenMemory 是理念上最接近 memfade 的方案**：
自适应衰减、共激活强化、可解释的召回轨迹——这三条 memfade 都有对应的设计。
差别在栈：它是 TypeScript 服务，要自己接宿主、自己管 embedding；
memfade 是 Python 单文件库 + 五个宿主适配器，复用宿主已配好的模型。

### 1.2 memfade 明确不追的东西（这是取舍，不是缺陷）

- 不做多租户服务与鉴权：memfade 的作用域模型是**会话**，
  不是**账户**。要按用户隔离，得自己在宿主层做。
- 不做知识图谱与实体链接：图能解决"张三是同一个人吗"，
  memfade 靠主语纪律 + 关键词匹配处理，粗糙但零依赖。
- 不做 agent 自主编辑记忆：Letta 那种"agent 自己决定改自己的记忆"，
  在聊天机器人场景里不可控——用户说什么就记什么才是可预期的。

## 二、同场竞技：Bot 记忆插件

详见 [`RESEARCH.md`](RESEARCH.md)（搜了 13 个 QQ bot 记忆插件的完整记录）。
这里只说结论。

那一档插件的典型形态是：

    聊一句 → 问 LLM「这段值得记吗」→ 存进向量库 → 检索 → 塞回 prompt

它们的共同短板：

| 短板 | 说明 |
|---|---|
| **没有衰减** | 记忆要么在库要么不在。靠"最近 N 条"或向量相似度排序代替遗忘，于是**旧事反复被提起**——这正是 memfade 的起点问题 |
| **没有写入纪律** | LLM 说值得记就记。问一句"今天状态怎么样"可能被记成一条稳定事实 |
| **作用域常是摆设** | 群聊与私聊共用一份库，或者干脆全局共享。A 在群里说的话被塞进 B 的私聊 |
| **不可审计** | 改错了只能清库重来，说不清哪条是从哪句话来的 |
| **要么绑死框架，要么自建依赖** | 装的时候要拖 Chroma/Qdrant/Neo4j 进来 |

memfade 对这五条逐条给了答案：

| memfade 的做法 | 对应上面哪条 |
|---|---|
| 四档淡化（ACTIVE / FADING / GISTED / ARCHIVED）+ 幂等艾宾浩斯 | 没有衰减 |
| 写入前纪律：主语纪律、依据原话对账、临时状态与情绪不入库、**工具路径同闸门** | 没有写入纪律 |
| 作用域键 + `cross_scope` 显式开启，**失败即闭**（没有全局兜底） | 作用域摆设 |
| `meta["quote"]` 存依据原话、单条改写、导出导入、体检工具随插件发货 | 不可审计 |
| 零第三方依赖 · 单文件 SQLite · 复用宿主 LLM 与嵌入 | 依赖负担 |

### 2.1 本机的直接竞品

MaiBot 上游曾经自带 **A_Memorix**（136 文件 / 2.9MB，
`stable_facts` + `episodic` + `graph_store` + `memory_lifecycle_policy`），
现已退场。memfade 与它的路线差别很清楚：

| | A_Memorix | memfade |
|---|---|---|
| 知识图谱 | 有 | 无 |
| 生命周期策略 | 有（策略驱动） | 有（淡化梯度 + 幂等衰减） |
| 依赖 | 需装图存储与模型 | 零第三方依赖 |
| 写入纪律 | 抽取为主 | 抽取 + 显式闸门（工具路径也拦） |
| 审计 | 弱 | 依据原话 / 导出 / 改单条 / 体检 |

## 三、memfade 的真差异（七条）

1. **淡化引擎四档 + 幂等艾宾浩斯。**
   别人的"遗忘"多半是二值开关或热度排序；memfade 是一条有档位的坡道，
   并且**始终按锚点时刻重算**——维护任务跑一次、跑两次、隔一天再跑，结果完全一致。
2. **写入前纪律。**
   主流库管的是"存下来之后怎么排"，memfade 还管"**该不该存**"：
   依据原话对账、常态与这一次分开、临时状态与情绪不入库、
   **模型自己调"记住"工具时也走同一道闸门**（这条曾漏过一条游戏数据进库）。
3. **零第三方依赖 + 单文件 SQLite。**
   整个核心不 import 任何第三方包（numpy 可选，有就用没有就退回纯 Python），
   库就是一个 `.db` 文件——拷贝、备份、迁移、审计都是文件操作。
4. **会话隔离失败即闭。**
   检索只有一条过滤条件：`scope_key = 当前会话 OR cross_scope = 1`。
   **没有"找不到就退回全局"的兜底**——宁可这条消息没有记忆可用。
5. **可审计。**
   每条记忆带依据原话；能导出、能导入、能改单条、能体检。
   体检工具**随插件一起发货**（`audit_db` / `verify_against_chat` / `edit_memory`），
   不是让用户自己拼。
6. **五个宿主适配器 + HTTP 侧车。**
   MaiBot / LangBot / AstrBot / NoneBot2 / Koishi，再加一个能给任何语言调的 HTTP 侧车。
   别人多是"库"，接宿主是自己的事。
7. **零配置。**
   复用宿主已配好的 LLM 与嵌入，不让用户再填一份 API key——
   这是"装上就用"和"读三页文档先申请 API key"的区别。

## 四、诚实的差距（七条）

写下来是因为不写就会被用户自己发现：

1. **没有图与实体链接。** "张三"和"小张"是不是同一个人，memfade 答不了。
   Graphiti / A-MEM / mem0 在这点上更强。
2. ~~**没有 reflect 与佐证链。**~~ **已补齐（v0.4.2）**：新增 `OBSERVATION` 种类与
   `_reflect_pass`，能从多条记忆归纳出高层结论，每条结论带 `meta["derived_from"]` 佐证链。
   详见 `ARCHITECTURE.md`「观察归纳（reflect）」章节。
3. **没有服务化与鉴权。** 多用户 SaaS 场景直接出局。
4. **没有重排模型。** 召回靠向量 + 关键词融合打分，没有 cross-encoder rerank。
5. **没有公开基准。** memfade 有 `bench_decay` / `bench_memory_quality`，
   但**没有跑过 LoCoMo / LongMemEval / memorylens-bench**，
   所以"记忆质量比 X 好"这类话目前没有第三方可核对的依据。
   （Hindsight 自报 LongMemEval 91.4%、ZEP 平台自报 LoCoMo 94.7%——
   **厂商自报分数**只能当参考，不能当结论。）
6. **没有 MCP server。** OpenMemory、Hindsight、mem0 都有，memfade 只提供 HTTP 侧车。
7. **提示词与门槛偏中文语境。** 抽取纪律写的是中文，
   英文语料上的表现没有验证过。

## 五、什么时候该选别人

诚实的插件要写清楚自己的边界：

| 你的情况 | 该选 |
|---|---|
| 要给几十万人提供服务，要鉴权、审计、多租户 | mem0 平台 / Hindsight |
| 要回答"上个月的她住哪"这种时间点真相 | Graphiti |
| 要 agent 自己管理自己的记忆（MemGPT 式） | Letta |
| 只用 SillyTavern / Open WebUI，想要个记忆开关 | 它自带的，别装插件 |
| TS 生态、要 MCP、要可解释召回轨迹 | OpenMemory |
| 只想「记住 / 忘掉」两个按钮，懒得装库 | AstrBot 生态那几百行的插件够用 |
| **QQ 机器人 + 不想再运维一套记忆服务 + 记错了要能查能改** | **memfade** |

- 星标与能力：2026-11-03 当天 GitHub 项目页与官方 README。
