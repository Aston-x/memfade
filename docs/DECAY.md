# 记忆淡化算法

这是 memfade 的核心。本文把每个设计选择背后的理由写清楚，
尤其是「为什么不那么做」。

## 1. 双轴：重要 ≠ 持久

多数记忆库只有一个字段管这件事，通常叫 `importance` 或 `score`。
问题在于「这条内容多重要」和「它现在还剩多少」是两回事：

* 「他叫许杏玖」——重要，但新鲜度无关紧要；
* 「今天中午吃了炸鸡」——刚发生时不重要，两周后就不该再被提起。

把它们压成一个字段，结果是：

* 重要事实跟着时间一起掉分（因为它在同一个字段里被衰减）；
* 一次性事件因为「刚写入时分数高」而反复被提起。

memfade 拆成两条轴：

| 轴 | 含义 | 随时间变化？ | 谁决定 |
|---|---|---|---|
| `importance` | 这条内容本身有多重要 | **不变** | 抽取器（LLM + 规则） |
| `strength` | 这条记忆现在还剩多少 | **变** | 时间 + 回忆次数 |

`importance` 影响两件事：检索权重，以及这条记忆能活多久（见下）。
`strength` 只回答「此刻还想不想得起来」。

## 2. 稳定性

```
stability_days = base_stability(种类)
                × (1 + importance_gain × importance)
                × min(ceiling, growth ^ recall_count)
```

三个因子分别回答三个问题：

1. **种类基数**——事件天生比事实易忘。默认 `episodic` 3 天、`semantic` 30 天。
2. **重要性加成**——越重要越经得起时间。
3. **复习增长**——被反复想起的记忆越来越稳。这是**间隔重复**：
   每次回忆都把稳定性往上抬一格，但有上限（默认 8~12 倍），
   防止少数几条被反复提起的记忆钉死在那里。

## 3. 保留率

```
effective_strength(now) = strength × exp(-Δdays / stability_days)
```

经典艾宾浩斯指数曲线。三个实现细节值得强调：

### 3.1 幂等：按锚点重算，不是逐日相乘

错误做法：

```sql
UPDATE memories SET strength = strength * 0.99
```

这在重启、多实例、定时器抖动时会重复衰减，把记忆洗白。

memfade 的做法是**永远从「锚点时刻的强度」按时间差重算**：

```python
elapsed = (now - memory.anchor_at) / 86400
return memory.strength * exp(-elapsed / stability)
```

于是整理任务跑一次、跑两次、隔一天再跑，结果完全一致。
`tests/test_decay.py::test_idempotent` 和
`tests/test_consolidate.py::test_consolidation_is_idempotent` 钉死了这条。

### 3.2 档位可以一次跨多档

一条三周没被提起的一次性事件，不该在「淡出」上再卡三周才轮到「成 gist」。
所以档位求解按**绝对阈值**定目标，而不是一级一级往下走。

### 3.3 迟滞：施密特触发器

档位边界上必须有迟滞带，否则整理任务每跑一次，记忆就在 ACTIVE 与 FADING
之间来回抖。做法是标准的施密特触发器：

```
跌破 fade_exit  → 降级
升过 fade_enter → 恢复
两条线之间      → 粘住，不动
```

`tests/test_decay.py::test_no_oscillation_in_sticky_band` 验证这一点。

## 4. 淡化梯度

```
ACTIVE ──eff < fade_enter──▶ FADING ──eff < gist_threshold──▶ GISTED
                                                                 │
                                        ARCHIVED ◀──eff < archive_threshold
```

| 档位 | 召回 | 注入 |
|---|---|---|
| `ACTIVE` | 是 | 事实层，当作现在仍然成立的知识 |
| `FADING` | 是 | 回声层，带「可能已经变了」的标记，限量 |
| `GISTED` | 是（极低权重） | 只带一行摘要 |
| `ARCHIVED` | 否 | 完全不进上下文，原文仍在库里 |

**为什么要 gist 这一档？**

只有「留」和「删」两个选项时，用户会抱怨「老提旧事」；
只有「全留」时，模型会被噪声淹掉。gist 是中间态：
细节已经不可考，但「我们一起吃过炸鸡」这件事还在。
按需生成（LLM 一次调用），不生成也不影响别的档位。

**为什么归档不删？**

删了就回不来了，而「这条记忆到底该不该被忘掉」是个可能出错判断。
归档保留原文，随时可以人工捞回来——这跟 A_Memorix 的软删思路一致。

## 5. 强化：被想起才算数

记忆被**真正注入上下文**之后才做强化：

```
new_strength = eff + α × (1 - eff)      α = 0.35
anchor_at    = now
recall_count += 1
```

这是**残留学习**（residual learning）：不是恢复到 1.0，
而是在现有强度上按比例回升。回升幅度越小，越接近「已经有点忘事」的真实感受。

### 5.1 冷却期：防止正反馈刷分

如果「一被检索就变强 → 变强更容易被检索」，少数几条记忆会迅速霸榜。
所以强化有冷却期（默认 1 小时）：同一条记忆在冷却期内被再次召回不重复强化。

### 5.2 在召回时强化还是在注入时强化？

在**注入时**。被检索到但没进 prompt 的记忆，说明这一轮它并不重要，
不该因此变强。

## 6. 检索打分

```
score = 0.34 × rel
      + 0.20 × importance
      + 0.22 × (0.35 + 0.65 × strength_eff)
      + 0.14 × recency
      + 0.10 × freq
```

### 为什么不用纯乘法

Engram 用的是 `relevance × importance × strength × recency`。
乘法有个致命问题：**任何一项接近 0，总分就归零**。
一条高度相关但刚写入、strength 尚在爬坡的记忆会被彻底埋掉。

所以 memfade 用加权和，每个分量都归一化到 [0,1]。

### 为什么强度项要有下界

```
(0.35 + 0.65 × strength_eff)
```

强度低只会**打折**，不会**清零**。这条借鉴自 congling 的经验。
不然一条刚被强化的重要事实，因为强度从 1.0 掉到 0.9 就会损失 22% 的权重——
太敏感了。

### recency 和 strength 有什么不同

* `strength` 是「距上次**被想起**多久」——记忆自己的复习史；
* `recency` 是「距上次**有新信息**多久」——记忆的新鲜度。

一条三周没被提但昨天刚确认过的事实，strength 低、recency 高，
两个信号互相补充。

## 7. 候选生成

三条通道取并集：

1. **FTS5 二元组检索**——中文用字符二元组，不依赖分词器；
2. **向量检索**——可选，没有 embedding 就跳过；
3. **近期写入**——刚聊完的事一定要能召回，不能只靠语义相似度。

## 8. 关联加成

首条命中如果提到「炸鸡」，其它也提到「炸鸡」的记忆获得小幅加成。
这是「激活扩散」的轻量版：不做图结构，只看内容词重合，
代价几乎为零，但能捞出「说的是同一件事」的旁支记忆。

## 9. 去重

两层判定：

1. **归一化哈希**——去标点、空格、大小写后完全相同；
2. **Dice 系数**——`2|A∩B| / (|A|+|B|)`。

为什么不用包含度（交集 / 较短者）：包含度在「短句完全是长句的子集」
时会给 1.0，于是「二十块加价仲裁还没解决」和
「二十块加价仲裁还没解决呢」会被判成完全相同——多一个语气词而已。

为什么不用 Jaccard：记忆摘要常常是原文的缩写，两者长度天然不等，
Jaccard 对长度差过于敏感。

### 阈值分工

| 场景 | 阈值 | 性质 |
|---|---|---|
| 写入时拦截重复 | 0.82 | 非破坏性，宁可多拦 |
| 整理时合并 | 0.92 | 破坏性，必须有把握 |

### 合并不删数据

被合并方的原文进 `meta.merged_from`，可追溯、可回滚。

## 10. 矛盾仲裁

同 `(subject, predicate)` 但 `object` 不同的两条记忆 = 互相矛盾的事实。
新的取代旧的，旧的标记 `superseded`（**保留原文做证据链**，不进上下文）。

这跟「删掉旧事实」的区别在于：将来可以回答「你以前是怎么说的」。
